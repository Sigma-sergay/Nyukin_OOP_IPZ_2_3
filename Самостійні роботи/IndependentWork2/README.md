# Самостійна робота №2. Перевантаження конструкторів

Проєкт `IndependentWork2`. Запуск: `dotnet run`.

## Реалізація

Клас `Product` має п'ять приватних полів (`_id`, `_name`, `_price`, `_category`, `_stockCount`), п'ять властивостей **тільки для читання** (`Id`, `Name`, `Price`, `Category`, `StockCount`) та три конструктори:

1. **Основний** `Product(int id, string name, decimal price, string category, int stockCount)`: перевіряє дані й ініціалізує всі поля.
2. **Швидкий** `Product(int id, string name, decimal price)` : `this(id, name, price, "Uncategorized", 0)`: викликає основний.
3. **Копіювання** `Product(Product other)` : `this(other.Id, other.Name, other.Price, other.Category, other.StockCount)`: теж викликає основний, тому вся валідація лишається в одному місці й немає дублювання коду. Перевірка `other` на `null` винесена в допоміжний метод `Guard`, бо аргументи `this(...)` обчислюються до тіла конструктора.

Метод `ToString()` перевизначено за зразком з завдання. У `Main` встановлено українську культуру, щоб формат `{Price:C}` показував гривні.

## Вивід програми

```
Створення товарів
Товар 1 (основний конструктор): ID: 101, Name: Laptop, Price: 35 000,00 ₴, Category: Electronics, Stock: 15
Товар 2 (скорочений конструктор): ID: 102, Name: Mouse, Price: 800,00 ₴, Category: Uncategorized, Stock: 0
Товар 3 (конструктор копіювання): ID: 101, Name: Laptop, Price: 35 000,00 ₴, Category: Electronics, Stock: 15

Копія - це окремий об'єкт: True
```

## Відповіді на контрольні запитання

**1. Навіщо потрібне перевантаження конструкторів у класі `Product`?**
Товари додаються з різним рівнем деталізації: іноді відомі лише `id`, назва і ціна, іноді повний набір характеристик, а іноді потрібно створити дублікат. Перевантаження дає кілька зручних способів створення об'єкта з одним іменем конструктора, не змушуючи викликача передавати зайві значення чи створювати незрозумілі «порожні» об'єкти.

**2. Чому конструктор копіювання зручно реалізовувати через `this(...)`?**
Він делегує створення основному конструктору, тому валідація й ініціалізація полів написані в одному місці; не дублюється код присвоєння полів; якщо додасться шосте поле, змінюється лише основний конструктор і копіювальний (передати ще один аргумент); немає ризику, що копія оминула перевірки.

**3. Які переваги дає read-only доступ до властивостей після створення об'єкта?**
Об'єкт стає **незмінним** (immutable): стан задається один раз у конструкторі, тому його не можна випадково чи зловмисно зіпсувати; такі об'єкти безпечно передавати між частинами програми й потоками, ними легко користуватись як ключами та ділитись без копіювання; простіше міркувати про код, бо значення не міняється після створення. Копія (`Product(Product other)`) дозволяє отримати новий об'єкт на основі старого.

**4. У яких випадках перевизначення `ToString()` корисне?**
Коли об'єкт треба вивести в консоль, лог чи інтерфейс у зрозумілому вигляді (`Console.WriteLine(product)` покаже дані, а не назву типу `IndependentWork2.Product`), під час налагодження (відлагоджувач показує `ToString()`), у повідомленнях про помилки, а також при формуванні рядкового представлення для інтерполяції та `string.Join`.
