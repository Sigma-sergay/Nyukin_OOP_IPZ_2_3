# Лабораторна робота №6 — Наслідування (варіант 19)

**Тема:** наслідування, ключові слова `base`, `virtual`, `override`, приховування членів (`new`).

## Реалізована ієрархія

`Account` → `UserAccount`, `AdminAccount`

| Клас | Поля / властивості | Методи |
|---|---|---|
| `Account` (базовий) | `Username`, `PasswordHash` (приватні поля + публічні властивості) | конструктор; `virtual void Login()`; `string GetAccountType()` (не virtual) |
| `UserAccount : Account` | `Email` | конструктор з `base(...)`; `override void Login()`; `void ChangePassword()`; `new string GetAccountType()` |
| `AdminAccount : Account` | `AccessLevel` | конструктор з `base(...)`; `override void Login()`; `void GrantPermissions()` |

- `override` у `Login()` дає поліморфізм: виконується метод реального типу об'єкта.
- `new` у `UserAccount.GetAccountType()` приховує метод базового класу: вибір методу залежить від типу посилання.

dotnet run

## Відповіді на контрольні запитання

### 1. Принцип наслідування в ООП. Приклад з реального світу

Наслідування дозволяє створити новий (похідний) клас на основі наявного (базового): похідний клас отримує його поля та методи й може додати власні або змінити успадковані. Так формується ієрархія «є різновидом» (is-a), а спільний код пишеться один раз у базовому класі.

Приклад із реального світу: «транспортний засіб» має марку, рік випуску та вміє їхати. «Автомобіль» і «мотоцикл» є різновидами транспортного засобу: вони мають усе те саме, але автомобіль додатково має кількість дверей і багажник, а мотоцикл може мати коляску. У нашій роботі так само `UserAccount` та `AdminAccount` є різновидами `Account`: вони успадковують `Username`, `PasswordHash` і `Login()`, а кожен додає своє (`Email`, `AccessLevel`).

### 2. Для чого використовується `base`

`base` дає доступ до членів базового класу з похідного. Основні застосування:

1. **Виклик конструктора базового класу.** Базовий клас має ініціалізувати свої поля, тому похідний передає йому параметри:
   ```csharp
   public UserAccount(string username, string passwordHash, string email)
       : base(username, passwordHash) { ... }
   ```
2. **Виклик версії методу з базового класу всередині override**, щоб розширити поведінку, а не замінити її повністю:
   ```csharp
   public override void Login()
   {
       base.Login();               // спільна частина
       Console.WriteLine("...");   // додаткова поведінка UserAccount
   }
   ```
3. **Доступ до прихованого члена базового класу** (наприклад, `base.GetAccountType()` у класі, що використав `new`).

### 3. Різниця між `virtual` та `override`. Як вони забезпечують поліморфізм

- `virtual` ставиться в **базовому** класі й повідомляє: цей метод дозволено перевизначати в похідних класах. Він має власну реалізацію за замовчуванням.
- `override` ставиться в **похідному** класі й означає: цей метод замінює віртуальний метод базового класу з тією самою сигнатурою.

Поліморфізм працює так: змінна типу `Account` може посилатися на об'єкт `UserAccount` або `AdminAccount`. Під час виклику `acc.Login()` середовище виконання дивиться на **реальний тип об'єкта** (а не типу змінної) і викликає відповідний `override` (пізнє зв'язування через таблицю віртуальних методів). Тому один і той самий код `foreach (Account acc in accounts) acc.Login();` для різних об'єктів виконує різну поведінку.

### 4. Коли використовувати `new` і які наслідки

`new` потрібен, коли в похідному класі треба оголосити член з тим самим іменем, що й у базовому, але базовий метод **не є** `virtual` (або перевизначати його не можна чи не потрібно). Це **приховування**, а не перевизначення. Типові випадки: клас із бібліотеки, який ми не можемо змінити, або новий метод базового класу випадково збігся за іменем з уже наявним методом похідного.

Наслідки:

- Вибір методу відбувається на етапі компіляції **за типом посилання**. `UserAccount userRef` викличе версію з `UserAccount`, а `Account baseRef = userRef` (той самий об'єкт) викличе версію з `Account`.
- Поліморфізм не працює, і це джерело помилок: код, що працює з базовим типом, не побачить нової поведінки.
- Без `new` компілятор видасть попередження CS0108, тож `new` фактично каже: «я свідомо приховую цей член».

Тому, якщо потрібен поліморфізм, правильніше використовувати `virtual` + `override`, а `new` лишати для рідкісних випадків.
